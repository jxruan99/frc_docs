FRC 机器人综述

一台 FRC 机器人可以拆成四个部分：电气与控制、驱动系统、机械结构，以及把它们串起来的软件。这一篇是技术方向的入口：先建立整体框架，再按需要深入到主控制器、电机、传感器、机械机构等专题。

适用于 2027 赛季具体规则以当年 Game Manual 为准

01整体架构

先看全貌。下图里，电力从电池出发，经过总断路器和配电板，分给控制器和执行器；信号从 Driver Station 发出，经无线电台到达主控制器，再由主控制器指挥电机控制器和气动模块；机械传动把电机和气缸的动作变成机构的运动；传感器再把机构的状态反馈给主控制器，形成闭环。

电气与控制 电力 控制

电池、断路器、配电板、主控制器、无线电台。大部分是 FIRST 规定的标准件，各队之间几乎一样。

驱动系统 执行

底盘、轮组、电机和电机控制器，决定机器人跑得多快、多灵活。多数强队使用市售的 swerve 轮组。

机械结构 机构

车架和完成当年任务的机构：取件、发射、升降、攀爬。这部分每年都要重新设计，最能体现各队的差异。

软件 程序

运行在主控制器上的程序，负责读取手柄和传感器、控制每个电机，并完成 15 秒的自动阶段。

02电气与控制系统

这部分的大多数部件由 FIRST 规定型号，或出现在官方零件包（Kit of Parts，KoP）里。各队能自由选择的余地不大，但接线质量对比赛成败影响极大：比赛中很多"机器人突然不动了"，原因都是一根松动的线。

部件常见型号作用
电池12V 18Ah 密封铅酸电池全车唯一电源。比赛时每场换一块充满的电池，各队通常备 6 块以上
总断路器120A 断路器全车总开关和总保险，要装在容易够到的位置，方便紧急断电
配电板REV PDH、CTRE PDP 2.0、AndyMark AMPD 等把电分成多路，每路装保险或断路器。PDH 有 20 个大电流通道和 3 个小电流通道
主控制器Limelight SystemCore（2027 起）机器人的大脑，运行学生写的程序。详见《SystemCore 主控制器》
无线电台Vivid-Hosting VH-109机器人和 Driver Station、场地系统之间的 Wi-Fi 6E 通信，有 4 个以太网口
信号灯 RSLAllen-Bradley 855PB 或 AndyMark am-3583规则要求必装的橙色灯，机器人启用时闪烁，提醒周围的人注意
电机控制器REV SPARK MAX / SPARK Flex，CTRE Talon FX（集成在 Kraken、Falcon 电机里）等接收主控制器的指令，控制电机转速、方向和力度，大多通过 CAN 总线通信
气动模块REV Pneumatic Hub、CTRE PCM控制压缩机和电磁阀，驱动气缸做直线推拉动作。不是每台机器人都用气动
主电源线6 AWG 线 + Anderson SB50 插头电池到断路器、配电板的大电流线路

传感器

传感器让程序"知道"机器人的状态，是自动阶段和精确控制的基础：

  • 编码器：测量轮子或机构转了多少圈、转多快。很多无刷电机内置编码器，绝对值编码器（比如 CTRE CANcoder）常用在 swerve 轮组和手臂关节上
  • IMU / 陀螺仪：测量机器人朝向。SystemCore 已内置，也有队伍另装 Pigeon 2 等
  • 相机与视觉：识别场地上的 AprilTag 标记来确定位置，或识别游戏道具。常用 Limelight 智能相机，或在协处理器上跑 PhotonVision
  • 限位开关、光电传感器、距离传感器：判断机构是否到位、道具是否进入

03驱动系统

驱动系统（drivetrain）就是机器人的"腿"。比赛中大部分时间都在跑位，所以底盘的速度、灵活性和可靠性往往比任何花哨的机构都重要。

底盘类型

类型原理优点缺点
Swerve（全向轮组）四个轮组，每个轮子都能独立转向和驱动可以朝任意方向平移，同时自由旋转，近年强队几乎都用贵（每个轮组要 2 个电机），编程更复杂，维护要求高
坦克式 / West Coast Drive左右两侧各一组轮子，靠两侧速度差转向简单、便宜、皮实，适合新队不能横向移动，对抗中容易被别人卡住
KoP 底盘FIRST 零件包里的 AndyMark AM14U 系列坦克底盘免费、有说明书，新队一两天就能组装好同上，性能一般
Mecanum（麦克纳姆轮）斜置滚子的轮子，也能横移结构比 swerve 简单推力小、怕撞，FRC 里已很少见

常见的市售 swerve 轮组有 SDS 的 MK4 / MK5 系列、REV MAXSwerve、WCP Swerve X2 等。绝大多数队伍直接购买轮组，而不是自己设计。

电机

  • 无刷电机是主流：WCP Kraken X60（内置 Talon FX 控制器）、Kraken X44，REV NEO、NEO Vortex（可直接插装 SPARK Flex）、NEO 550（小型）等
  • 电机必须在 FIRST 的合规清单上，每年以 Game Manual 为准
  • 电机转速很高、扭矩小，需要经过减速箱（齿轮、皮带或链条）变成机构需要的转速和力量。减速比怎么选，是机械组的核心计算之一

电机控制器

电机控制器夹在主控制器和电机之间：主控制器说"以 50% 的力转"或"转到 90 度"，电机控制器负责把电池的电按要求送给电机。现代控制器大多走 CAN 总线，并能在控制器内部直接跑闭环控制（比如按编码器读数自己调速）。2027 年起，老式的 PWM 控制器 Talon、Victor SP 不再合规。

04机械结构

机械结构分为两部分：承载一切的车架，和完成当年任务的机构（mechanism，也常叫 manipulator）。赛题每年不同，机构几乎每年都要重新设计，但下面这几类机构反复出现：

机构作用常见做法
取件 Intake从地面或人类玩家处收取游戏道具一排滚轮把道具卷进来，常配合可放下、收起的翻转结构
传送 Indexer在机器人内部移动、暂存道具皮带或滚轮组成的通道，配光电传感器判断道具位置
发射 Shooter把道具射向目标高速飞轮，转速闭环控制，常配可调角度的出射口
升降 Elevator把道具或机构举到不同高度多级伸缩滑轨，用绳索或皮带拉动
手臂 Arm / Pivot绕关节转动，改变角度大减速比电机驱动，绝对值编码器测角度
攀爬 Climber终局阶段把机器人挂起或升高钩子加绞盘或伸缩杆，需要承受整台机器人的重量

标准件与定制件

现在的 FRC 机械设计大量使用市售标准件（COTS，Commercial Off-The-Shelf），只在必要的地方做定制件：

  • 型材和板材：铝方管（常见 2×1 英寸、1×1 英寸，1/8 或 1/16 英寸壁厚）、铝板、聚碳酸酯板
  • 传动件：1/2 英寸和 3/8 英寸六角轴、轴承、齿轮、同步带（HTD）、链条（#25、#35）、减速箱
  • 常见供应商：WCP（West Coast Products）、REV Robotics、AndyMark、The Thrifty Bot、SDS、VEX Robotics、CTRE
  • 定制件：在 CAD 里设计，再用 CNC 雕刻机、3D 打印、激光切割或手工加工。设计工具首选 Onshape，对 FRC 队伍免费
规则红线
  • 尺寸：底盘周长和高度有上限，比赛中机构伸出底盘的距离也有限制
  • 重量：不含保险杠和电池，大约 115–125 磅（具体以当年规则为准）
  • 保险杠：必须按规定制作，显示队号和联盟颜色
  • 成本：单个零件和整机成本有上限

05软件

软件把硬件串成一个整体。程序跑在主控制器上，用 Java、C++ 或 Python 加 WPILib 库编写，最常见的是 Java。主流的程序结构是 Command-based（基于命令）：

  • Subsystem（子系统）：对应一个机构，比如底盘、手臂、发射器。它封装这个机构的电机和传感器
  • Command（命令）：一个动作，比如"把手臂转到 45 度"或"发射一次"。手柄按键触发命令，自动程序把多个命令串起来

软件组最大的优势是不用等机器人造好：用 WPILib 的仿真器，可以在电脑上先把程序和自动路线写好、测好。具体做法见《开发环境与仿真》。

06设计和开发机器人的关键步骤

下面是一支成熟队伍在赛季中的典型流程。时间按 1 月初 Kickoff、3 月初第一场比赛估算，各队会有出入。

  1. 读规则、拆赛题Kickoff 当天至第 1 周

    全队精读 Game Manual，把计分规则、机器人限制、犯规条款整理出来。很多设计失误都源于读漏了一条规则。

  2. 定策略、排优先级第 1 周

    算清楚每个得分动作值多少分、要多少时间，决定机器人"要做什么、不做什么"。核心原则：把少数几件事做得又快又稳，胜过什么都做但都不可靠。

  3. 做原型第 1–2 周

    用木板、废料、手钻快速做出取件、发射等机构的原型，验证想法能不能行。原型阶段要快、要便宜、可以丑。

  4. CAD 设计第 2–3 周

    在 Onshape 里做整车设计：底盘、各机构、电气布局、重量预算。先定底盘和整体布局，再细化机构。

  5. 加工与装配第 3–5 周

    按图纸加工零件、组装。底盘最好先完成，交给软件组和驾驶员尽早开始练习。

  6. 接线与装配同步

    按事先规划的布局走线，给每根线和每个 CAN 设备贴标签，记录 CAN ID。接线要整齐、牢固、便于检修。

  7. 编程与调试从第 1 周开始

    软件组在仿真器里先写好子系统、命令和自动路线；机器人一能动，就上车调 PID 参数、校准传感器。

  8. 测试与驾驶练习第 5 周起

    反复跑完整的比赛流程，找出会坏的地方。驾驶员练习时间越多越好，这往往是成绩差距最大的来源。

  9. 比赛与迭代比赛期

    每场比赛后复盘：什么坏了、什么慢了、对手怎么打。两场比赛之间持续改进。

07注意事项

  • 重量从第一天就要管。在 CAD 里给每个部分做重量预算，否则最后很可能超重，被迫临时减重。
  • 为维修而设计。比赛间隙往往只有十几分钟，常坏的部件要能快速拆换，常用工具尽量统一。
  • 接线是可靠性的命门。电源线要压紧、固定，CAN 线要防止被机构夹断，主控制器和电台要远离金属碎屑。
  • 先让底盘动起来。能跑的底盘越早交付，驾驶练习和软件调试就能越早开始。
  • 代码要做版本管理。用 Git 保存每一个能用的版本，比赛现场改坏了可以马上退回。
  • 备件和电池。常坏的零件、电机控制器、电池都要有备份，比赛前列清单检查。
  • 安全第一。车间里有电动工具和高速运动的机构，护目镜必须戴；调试时机器人周围不能站人，随时准备按急停。
  • 赛前自查。按检录清单（Inspection Checklist）提前自查：尺寸、重量、保险杠、电气规范。

08技术方向路线图

这一篇是技术方向的入口。后续专题按"从控制到执行、从软件到机械"的顺序展开：

  • 02SystemCore 主控制器硬件规格、接口、功能模块，和 roboRIO 的区别已完成
  • 03开发环境与仿真安装 WPILib，在仿真器里跑起第一个程序，Driver Station 入门已完成
  • 04电机与电机控制器常见电机对比、CAN 配置、电流限制、闭环控制和 PID 入门计划中
  • 05传感器与视觉编码器、IMU、限位开关，AprilTag 定位，Limelight 与 PhotonVision计划中
  • 06底盘与 Swerve底盘选型、swerve 原理、里程计与场上定位计划中
  • 07机械机构设计取件、升降、手臂、发射、攀爬的典型设计和计算计划中
  • 08电气接线与布线电源和 CAN 布线、做线工具、检录要求、故障排查计划中
  • 09程序架构Command-based 框架、子系统划分、代码组织和 Git计划中
  • 10自动程序与路径规划自动阶段设计、PathPlanner、轨迹跟随计划中
