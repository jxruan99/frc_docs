CAN 数据总线

CAN 总线是 FRC 机器人的"神经网络"：主控制器通过它指挥所有电机控制器，也通过它读回电机、编码器、陀螺仪和配电板的数据。它可靠、省线，但一个松动的接头也可能让半台机器人失灵。这一篇讲 CAN 的原理、接线规范和排查方法。

资料整理于 2026 年 10 月适用于 2027 赛季 SystemCore

01CAN 是什么

CAN（Controller Area Network，控制器局域网）最早是为汽车设计的通信总线，现在的汽车里有几十个控制单元都靠它通信。它的特点：

  • 两根线串起所有设备：CAN-H（FRC 惯例用黄色线）和 CAN-L（绿色线），绞在一起，从一个设备连到下一个设备
  • 广播式通信：任何设备发出的消息，总线上所有设备都能收到，每个设备只处理和自己有关的消息
  • 按优先级自动排队：几个设备同时发送时，消息 ID 越小优先级越高，高优先级的消息先发，不会互相冲突
  • 抗干扰强：两根线传的是一对相反的信号（差分信号），电机产生的电磁干扰会同时影响两根线，接收端相减就能抵消

02为什么 FRC 用 CAN

早年 FRC 的电机控制器多用 PWM 信号：每个控制器单独一根信号线接到主控制器，只能单向发送"转多快"。CAN 带来了几个关键变化：

PWMCAN
接线每个设备一根线，独占一个接口一条总线串起几十个设备
数据方向单向：只能发指令双向：发指令，也读回转速、位置、电流、温度、故障
配置基本不能配置可以远程设置电流限制、PID 参数、反转等
闭环只能在主控制器上算可以让电机控制器在内部跑闭环
现状2027 年起老式 PWM 控制器不再合规FRC 的绝对主流

现在挂在 CAN 上的设备包括：电机控制器（Talon FX、SPARK 等）、配电板（PDH）、气动模块、CANcoder 编码器、Pigeon 2 陀螺仪、CANrange 等距离传感器。

03总线拓扑：一条链，两端各一个终端电阻

FRC 的 CAN 总线是菊花链：从主控制器出发，线依次穿过每个设备（进一组线、出一组线），最后到达链尾。链的两端各有一个 120 Ω 终端电阻，用来吸收信号反射，缺一个都可能导致通信失败。

  • 不要做星形或长分支：从总线上拉出很长的支线接设备，会造成信号反射。设备应当"串"在链上
  • 终端电阻在哪里：很多设备内置可开关的终端电阻，比如 REV PDH 的终端电阻开关、CTRE CANivore 可在软件里开关。主控制器一端是否内置终端，请以 SystemCore 的官方说明为准

04CAN 2.0 与 CAN FD

CAN 2.0（经典 CAN）CAN FD
速率FRC 中为 1 Mbps数据部分可以切换到更高速率（标准最高约 10 Mbps）
每帧数据量最多 8 字节最多 64 字节
FRC 中的位置roboRIO 自带 1 路SystemCore 自带 5 路；roboRIO 时代要外接 CTRE CANivore 才有
效果设备一多，总线容易拥挤同样的数据占用更少的总线时间。CTRE 的测试中，一条在经典 CAN 上占用 80% 的总线，换到 CAN FD 后约为 35%

CAN FD 兼容经典 CAN 设备，但一条总线上只要有经典 CAN 设备，整条总线就只能以经典模式运行。所以规划时，最好把支持 CAN FD 的设备（比如 CTRE 的 Talon FX、CANcoder、Pigeon 2）放在同一条总线上。

05设备 ID

总线上每个设备都由"厂商 + 设备类型 + 设备编号"唯一确定。设备编号（CAN ID）由队伍自己设置，通常范围是 0–62：

  • 同一类型的设备 ID 不能重复：两个 Talon FX 都是 ID 1 会冲突；但一个 Talon FX 和一个 CANcoder 都是 ID 1 没问题
  • 新设备出厂 ID 通常相同：每次只接一个新设备上总线，改好 ID 再接下一个
  • 用厂商工具设置：CTRE 设备用 Phoenix Tuner X，REV 设备用 REV Hardware Client

建议给 ID 定一套编号规则，并做成表格贴在机器人上。下面是一个 swerve 机器人的示例：

ID 段设备所在总线
1–4四个轮组的驱动电机（左前、右前、左后、右后）底盘总线
11–14四个轮组的转向电机底盘总线
21–24四个轮组的 CANcoder底盘总线
30Pigeon 2 陀螺仪（如果不用 SystemCore 内置 IMU）底盘总线
40–49机构电机：取件、传送、发射、电梯、手臂机构总线
1配电板 PDH机构总线

06接线要点

  • 颜色不能接反：黄接黄（CAN-H），绿接绿（CAN-L）。接反了整条总线都可能无法通信
  • 使用双绞线：两根线绞在一起，抗干扰能力强。按设备说明书选择线规
  • 接头要牢：压接要用合适的工具和端子，焊接要做好热缩保护。撞击和振动是接头松脱的主要原因
  • 远离运动部件：CAN 线被链条、齿轮夹断，是比赛中常见的故障
  • 做好应力释放：用扎带把线固定在车架上，不要让接头本身承受拉力
  • 线要能检修：走线位置要方便查看和更换，不要埋在拆不开的结构里面
检查终端电阻的小技巧

断电后，用万用表测 CAN-H 和 CAN-L 之间的电阻：两个 120 Ω 终端电阻并联，读数应约为 60 Ω。读数约 120 Ω，说明只有一个终端电阻，或者总线中间断开了；读数接近 0，说明两根线短路了。

07总线负载

总线负载（bus utilization）指总线有多少比例的时间在传数据。设备越多、每个设备汇报得越频繁，负载就越高。负载太高时，消息会排队、延迟，控制变得迟钝，甚至丢失数据。

  • 在哪里看：Driver Station 和厂商调试工具都能显示 CAN 负载和错误计数
  • 降低汇报频率：每个设备会周期性地汇报状态。用不到的数据，可以在厂商库里调低汇报频率或直接关闭
  • 用 CAN FD：同样的数据占用更少的总线时间
  • 分成多条总线：见下一节

08多总线规划

SystemCore 有 5 路 CAN-FD 总线，常见的分法是：

  • 底盘一条：swerve 的 8 个电机、4 个 CANcoder、陀螺仪。底盘对时序要求最高，单独一条总线最稳定
  • 机构一条或两条：取件、发射、电梯、手臂等，再加上配电板和气动模块
  • 留一条备用：比赛现场某条总线出问题时，可以临时把设备改接到备用总线

程序里创建设备对象时，需要指定它在哪条总线上。具体写法以 WPILib 2027 和厂商库的文档为准。

09故障排查

  1. 看指示灯

    每个 CAN 设备都有状态灯，对照厂商说明书判断：是没电、没收到 CAN 信号，还是正常。一串设备里从某一个开始全部异常，问题多半就在它前面那段线上。

  2. 用调试工具扫描

    Phoenix Tuner X 或 REV Hardware Client 会列出总线上能看到的设备。缺了哪个，就重点检查它和它附近的接线。

  3. 量终端电阻

    断电测 CAN-H 和 CAN-L 之间的电阻，正常约 60 Ω。

  4. 逐段检查接头

    从主控制器开始，沿着链逐个检查接头，轻轻拉一拉线，看是否松动、断线或接反。

  5. 查 ID 冲突和固件

    两个同类设备 ID 相同、固件版本和软件库不配套，都会导致设备"在总线上但控制不了"。

比赛中某几个机构突然一起失灵
它们很可能在同一条总线的同一段上。先检查这一段的接头，尤其是靠近运动部件和容易被撞的位置。
机器人时好时坏，Driver Station 报 CAN 错误
典型的接触不良。用手轻轻晃动线束，观察错误是否随之出现；同时检查终端电阻和总线负载。
新加了一个电机后，原来正常的电机也不听使唤了
新设备的 ID 和已有设备冲突。断开新设备，改好 ID 再接回。
