开发环境与仿真

不需要机器人，也不需要 SystemCore。一台电脑、一两个小时，就能装好 FRC 的开发环境，在仿真器里让一台虚拟机器人动起来，并亲手改代码看到效果。

资料整理于 2026 年 10 月示例以 Java 为主预计用时 1–2 小时

01你将完成什么

  • 在自己的电脑上安装 WPILib 开发环境
  • 创建一个机器人项目，并在仿真器里运行
  • 用键盘代替游戏手柄，操控虚拟的电梯、手臂和底盘
  • 修改代码和参数，亲眼看到机器人行为的变化
  • 了解 Driver Station，以及 2027 赛季要做的切换

仿真为什么重要？在 FRC 里，机器人往往到造车期后半段才造好，而比赛只有短短几周。会用仿真的队伍，软件组从第一天就能开始写代码、测自动程序，机器人一造好就能直接上车调试。

02先选版本：2026 稳定版还是 2027 测试版

WPILib 每年发布一个新版本。现在（2026 年 10 月）有两个选择：

2026 稳定版2027 测试版（alpha）
对应硬件roboRIOSystemCore
稳定性成熟稳定，问题少还在频繁改动，每个 alpha 版之间可能不兼容
教程和示例网上的教程、视频基本都对得上大量旧教程已经对不上，比如 SmartDashboard 被新的 Telemetry 和 Tunables 接口取代
仿真完整可用可用，但文档还在更新
适合谁现在入门、学概念的家长和学生已经熟悉 WPILib、想提前适应新赛季的人
建议

现在先用 2026 稳定版入门。仿真、命令框架、PID 这些核心概念两个版本是一样的，用稳定版学习少踩坑。正式的 2027 版通常在 1 月 Kickoff 时发布，到时候按第 09 节的清单切换即可。

03安装 WPILib

WPILib 安装包把开发所需的一切都打包好了：专用的 VS Code、Java JDK、C++ 编译工具、Gradle 构建工具，以及仿真和调试工具。不需要另外安装 Java 或 VS Code。

系统要求

  • Windows：64 位 Windows 11（2027 版开始提供 Arm64 安装包）
  • macOS：Intel 和 Apple Silicon 都支持。2027 版要求 macOS 15 或更高
  • Linux：64 位 Ubuntu 等发行版，具体版本见当年说明
  • 硬盘留出至少 5 GB 空间。只写 Java 的话，普通笔记本就够用；写 C++ 对内存要求高得多

  1. 下载安装包

    打开 WPILib 的 GitHub 发布页 github.com/wpilibsuite/allwpilib/releases，找到 2026 的最新稳定版（标注 Latest、不带 alpha 或 beta 的那个），按系统下载对应文件：Windows 是 .iso，macOS 是 .dmg（注意区分 Arm64 和 Intel），Linux 是 .tar.gz。

  2. 运行安装程序

    • Windows：双击 .iso 文件挂载，运行里面的 WPILibInstaller.exe
    • macOS：双击 .dmg，运行里面的安装程序。如果系统提示"无法验证开发者"，到 系统设置 → 隐私与安全性 里点"仍要打开"

  3. 选择安装内容

    选 Everything（全部安装）。Tools Only 只装调试工具，不能写代码。如果问是否下载 VS Code，选 Download for this computer only。

  4. 等待安装完成

    需要几分钟到十几分钟。完成后桌面上会出现 "2026 WPILib VS Code" 快捷方式（macOS 上在应用程序里，可以拖到 Dock）。

  5. 确认安装成功

    打开这个 VS Code，左侧或右上角能看到红色的 WPILib 图标（一个"W"形状的 logo），就说明装好了。

注意
  • 一定要用 WPILib 自带的那个 VS Code，不要用你电脑上原有的 VS Code，否则缺少扩展和正确的 Java 版本。
  • 不同年份的 WPILib 可以同时安装，互不影响，各自有独立的 VS Code 快捷方式。

04创建第一个项目

WPILib 的所有功能都通过 VS Code 的命令面板调用：按 Ctrl+Shift+P（macOS 是 ⌘+Shift+P），或者点右上角的 WPILib 图标，再输入命令名称。

  1. 打开新建项目向导

    在命令面板里输入并选择 WPILib: Create a new project。

  2. 选择项目类型

    第一次建议选 Example（示例项目），语言选 Java，然后在列表里选 Elevator Simulation（电梯仿真）。示例项目已经写好了物理模型，打开就能玩。

    以后自己从头写机器人时，选 Template → Java → Command Robot，这是最常用的命令框架模板。

  3. 填写项目信息

    • Base Folder：选一个放项目的文件夹
    • Project Name：起个名字，比如 ElevatorSim
    • Team Number：填你们队的队号（仿真时用不到，但部署到真机时需要）
    • 勾选 Enable Desktop Support：一定要勾，否则不能仿真

  4. 生成并打开项目

    点 Generate Project，在弹出的窗口里选择在新窗口打开。第一次打开时 VS Code 会下载依赖，右下角可能显示进度，等它完成。

项目里最重要的代码在 src/main/java/frc/robot/ 下：Robot.java 是程序入口，常量通常放在 Constants.java，各机构的代码放在 subsystems/ 这类文件夹里。不同示例的文件结构略有不同。

05跑起仿真

  1. 启动仿真

    命令面板里选 WPILib: Simulate Robot Code。第一次会先编译，稍等片刻。弹出扩展选择时，勾选 Sim GUI 再确定。

  2. 认识 Sim GUI

    弹出的 Simulation GUI 窗口里有几个小面板，最常用的是：

    • Robot State：切换机器人状态：Disconnected、Disabled（禁用）、Autonomous（自动）、Teleoperated（手动）、Test
    • System Joysticks：电脑能识别到的输入设备，包括键盘和插上的游戏手柄
    • Joysticks：机器人程序"看到"的手柄槽位（Joystick[0]、[1]……）
    • NetworkTables：程序发布出来的各种数据，可以查看，也可以修改

  3. 把键盘接成手柄

    把 System Joysticks 里的 Keyboard 0 用鼠标拖到 Joysticks 面板的 Joystick[0] 槽位上。这样键盘就成了 0 号手柄。默认按键映射如下（Sim GUI 里可以查看和修改键盘设置，不同版本的菜单位置略有不同）：

    按键对应手柄输入
    A / D摇杆 X 轴（axis 0）
    W / S摇杆 Y 轴（axis 1）
    E / R第三个轴（axis 2）
    Z X C V按钮 1、2、3、4（按钮 1 通常就是"扳机"）

  4. 启用机器人

    在 Robot State 里点 Teleoperated。现在程序进入手动阶段，会响应"手柄"输入了。想停下来，点 Disabled。

  5. 停止仿真

    关闭 Sim GUI 窗口，或在 VS Code 底部的终端里按 Ctrl+C。改完代码后重新运行 Simulate Robot Code 即可。

看不到 Sim GUI？

最常见的原因是创建项目时没勾 Enable Desktop Support。补救方法：命令面板里运行 WPILib: Change Desktop Support Enabled Setting，打开它，再重新仿真。

06上手练习

下面几个练习从易到难，每个 10–20 分钟。都基于 WPILib 自带的示例项目，不同版本里文件名和常量名可能略有差异，找不到时用 VS Code 的全局搜索（Ctrl+Shift+F）找相近的名字。

练习 1：让电梯动起来 入门

目标：跑通仿真，理解"启用"和"手柄输入"。

  1. 打开上一节创建的 Elevator Simulation 项目，运行仿真
  2. 把 Keyboard 0 拖到 Joystick[0]，Robot State 切到 Teleoperated
  3. 在 Sim GUI 菜单 NetworkTables → SmartDashboard 里找到电梯的示意图（Mechanism2d），打开它
  4. 按住 Z（按钮 1），电梯升到目标高度；松开，电梯回到底部
  5. 切到 Disabled，再按 Z，电梯不再响应

学到什么：机器人只有在启用状态下才会执行动作，这是 FRC 最基本的安全机制。

练习 2：改目标高度 入门

目标：第一次改代码，看到效果。

  1. 在 Constants.java 里找到电梯目标位置的常量（名字里通常带 Setpoint，单位是米）
  2. 把数值改小一半，保存
  3. 重新运行仿真，按 Z，电梯只升到一半高度

学到什么：把可调的数字集中放在 Constants 里，是 FRC 代码的常见习惯。比赛现场改参数时，只需要动这一个文件。

练习 3：体会 PID 控制 进阶

目标：直观理解闭环控制里最重要的参数 kP。

  1. 在 Constants.java 里找到电梯的 kP（比例增益）
  2. 把它调小到原来的十分之一，运行：电梯升得很慢，甚至到不了目标
  3. 把它调大到原来的十倍，运行：电梯冲过头再弹回来，来回振荡
  4. 再试几个中间值，找一个"又快又稳"的数

学到什么：kP 太小反应迟钝，太大会振荡。真机调试时，学生要做的正是这件事，在仿真里先体会一遍，上车调参会快很多。PID 的原理见《闭环控制与 PID》。

练习 4：不改代码调手臂 进阶

目标：学会在程序运行中实时调参数。

  1. 新建一个示例项目，选 Arm Simulation（手臂仿真），运行仿真并接好键盘
  2. 在 NetworkTables 面板里展开 Preferences，能看到手臂的目标角度和 P 值
  3. 切到 Teleoperated，按住 Z，手臂转到目标角度
  4. 直接在面板里修改目标角度和 P 值，再按 Z，观察变化，不需要重新编译

学到什么：Preferences 让参数可以在运行时修改并保存，实际调车时非常省时间。

练习 5：在场地上开车 挑战

目标：体验底盘控制和自动阶段。

  1. 新建示例项目 Simple Differential Drive Simulation（简单差速底盘仿真）
  2. 运行仿真，接好键盘，在 NetworkTables → SmartDashboard → Field 里打开场地图
  3. 切到 Teleoperated，用 W S 前后、A D 转向，在场地上开车（如果没反应，看代码里用的是哪几个轴，把对应按键找出来）
  4. 切到 Autonomous，看机器人自动沿预设路线行驶
  5. 在代码里找到自动路线的终点坐标，改一个数，再看自动路线的变化

学到什么：同一台机器人既能手动开，也能按程序自动跑。自动阶段的 15 秒，就是靠这样的路线和定位完成的。

下一步

完成这些练习后，可以用 Template → Command Robot 新建一个空项目，试着自己写一个子系统。WPILib 官方文档的 Zero to Robot 和 Command-Based Programming 两部分是最好的教材。

07看数据的工具

机器人程序通过 NetworkTables 把数据发布出来，下面这些工具都能读取它们，仿真和真机都适用。它们都随 WPILib 一起安装。

工具用途连接仿真
AdvantageScope画数据曲线、回放日志、显示 2D 场地和 3D 机器人动画。调试和赛后分析的首选菜单 File → Connect to Simulator，或按 Ctrl+Shift+K
Elastic比赛时给驾驶员看的仪表盘，可以自由摆放各种控件设置里把服务器地址设为 localhost
Glass轻量的数据查看和调试工具，界面和 Sim GUI 类似NetworkTables 设置里，Team/IP 填 localhost

建议家长至少熟悉 AdvantageScope：学生调试时经常需要一起看曲线，判断是机械问题、电气问题还是程序问题。

08Driver Station

Driver Station（驾驶站）是操作手用来控制机器人的电脑程序，也是比赛中机器人和场地系统之间的桥梁。仿真时 Sim GUI 替代了它的大部分功能，但上真机时必须用它。

它能做什么

  • 启用和禁用机器人，选择 Autonomous、Teleoperated、Test 等模式
  • 连接手柄：Xbox、PlayStation 等游戏手柄插在电脑上，经 Driver Station 传给机器人，在 USB 设备页可以调整手柄的槽位顺序
  • 显示状态：通信是否正常、电池电压、程序是否在运行
  • 查看日志：程序打印的信息和错误，以及电压、通信质量等历史曲线

2027 年的变化

  • 到 2026 赛季为止：Driver Station 是 NI 公司 FRC Game Tools 里的 Windows 程序，只能在 Windows 上运行
  • 2027 赛季：换成新的 FIRST Driver Station，开始支持多个平台，不再只限 Windows。目前也在 alpha 测试中，版本需要和 WPILib、SystemCore 系统镜像配套使用（比如 WPILib 2027 alpha 7 要求 SystemCore 镜像 14 和 Driver Station Alpha 7）
安全须知
  • 启用机器人之前，确认周围的人都知道、都站在安全距离外
  • 记住急停方法。现行 Windows 版 Driver Station 中，空格键是紧急停止，Enter 是禁用。新版 Driver Station 的快捷键以正式版说明为准
  • 急停后机器人要重启才能再次启用，这是有意的设计

09切换到 2027 的清单

2027 正式版发布后（通常在 1 月 Kickoff 前后），按下面的清单切换：

  • 安装 2027 版 WPILib：和 2026 版并存，用新的 "2027 WPILib VS Code"
  • 语言版本升级：Java 25、C++23（安装包会自带对应的 JDK）
  • 新建项目，不要直接升级旧项目：2027 有大量不兼容的改动，按新模板重建，再把逻辑搬过去更稳妥
  • 界面数据接口变了：SmartDashboard 被新的 Telemetry 和 Tunables 接口取代，相关代码要改写
  • 删掉的旧功能：relay、SPI 传感器、模拟陀螺仪等，详见《SystemCore 主控制器》第 05 节
  • 厂商库：CTRE Phoenix、REVLib、PathPlanner 等都要换成 2027 版，AprilTag 和 CameraServer 也改成了单独的库
  • SystemCore 和 Driver Station：系统镜像、Driver Station、WPILib 三者版本要配套，按 WPILib 发布说明的要求升级

10常见问题

运行仿真时报错，说找不到 desktop 或 simulation 相关的任务
项目没开启桌面支持。运行 WPILib: Change Desktop Support Enabled Setting 打开它。
第一次构建很慢，或者卡在下载
第一次需要下载依赖，网络慢时可能要十几分钟。如果完全卡住，检查网络或代理设置，之后的构建会快很多。
Windows 防火墙弹窗，问是否允许 Java 访问网络
选择允许。仿真时 Sim GUI 和 AdvantageScope 要通过本机网络和程序通信。
按键盘机器人没反应
依次检查：Keyboard 0 是否拖到了 Joystick[0]；Robot State 是否是 Teleoperated；Sim GUI 窗口是否处于激活状态（键盘输入只在它被选中时有效）。
VS Code 里代码一片红色波浪线
多半是依赖还没下载完，或者用的不是 WPILib 自带的 VS Code。等右下角任务完成，或者用 WPILib 的 VS Code 重新打开项目。
Mac 上能不能写 C++？
可以，但需要先安装 Xcode 命令行工具。新手建议从 Java 开始，配置最简单。
