底盘与 Swerve

底盘是机器人的"腿"，也是整台机器人最先要做好的部分。这一篇比较 FRC 常见的底盘类型，重点讲近年强队几乎都在用的 swerve 全向底盘：它由什么组成、怎么算出每个轮子的方向和速度、软件怎么实现，以及从零调通的步骤。

资料整理于 2026 年 10 月代码示例以 Java 为主

01底盘为什么重要

  • 比赛大部分时间都在跑：取件、送件、躲避防守、终局抢位置，都靠底盘
  • 决定了自动阶段能做多少：底盘越快越准，15 秒内能完成的任务越多
  • 是其他一切的基础：机构装在底盘上，电气板、电池放在底盘里。底盘尺寸一定，整车布局就基本确定了
  • 越早完成越好：底盘一能跑，软件组就能调试，驾驶员就能练习。很多强队在 Kickoff 前就已经造好底盘

02底盘类型

类型能怎么动电机数量优点缺点
Swerve任意方向平移，同时自由旋转8 个（每个轮组 2 个）最灵活，便于躲避防守和对准目标；近年强队的标配贵、编程复杂、维护要求高
坦克式 / WCD前进后退、原地转向，不能横移4–6 个简单、便宜、推力大、皮实不能横移，侧面容易被推

新队伍怎么选

第一年或缺少经验的队伍，用 KoP 或简单的坦克底盘完全可以，把精力放在做好一两个得分机构上。有一定基础后，建议在休赛期先做一台 swerve 练手，不要在造车期第一次尝试。

03Swerve 轮组

swerve 底盘一般有四个轮组（module），装在底盘四角。每个轮组包含：

  • 驱动电机：让轮子滚动，决定速度
  • 转向电机：让整个轮子绕竖直轴转动，决定方向
  • 绝对值编码器：测量轮子当前朝向。开机时就要知道方向，所以必须用绝对值编码器，比如 CANcoder

绝大多数队伍直接购买市售轮组，常见的有 SDS 的 MK4 / MK5 系列、REV MAXSwerve、WCP Swerve X2 系列、The Thrifty Bot 的 Thrifty Swerve。它们通常提供几档驱动减速比（比如 SDS 的 L1 到 L3）：减速比小则跑得快、起步慢，减速比大则起步猛、最高速度低。常见的 FRC swerve 最高速度大约在 4–5.5 m/s。

04Swerve 运动学：每个轮子该朝哪、转多快

驾驶员想让机器人"一边往前走、一边逆时针转"。程序要据此算出四个轮子各自的方向和速度。原理是向量相加：

轮组速度 = 机器人平移速度 + 旋转带来的切向速度（ω × 轮组到中心的距离）
  • WPILib 已经替你算好：SwerveDriveKinematics 输入机器人期望速度（前后、左右、旋转，即 ChassisSpeeds），输出四个轮组的方向和速度（SwerveModuleState）
  • 速度超限时按比例缩小：某个轮子算出来超过最大速度时，四个轮子要一起按比例缩小，否则机器人的运动方向会走样
  • 不转超过 90°：如果轮子需要转 135°，不如只转 45° 再让驱动电机反转，效果一样还更快。WPILib 提供了这个优化
  • 反过来也能算：知道四个轮子的实际方向和速度，可以反推机器人整体在怎么动，这就是 swerve 里程计的基础

05以场地为参照驾驶

swerve 有两种驾驶方式：

  • 以机器人为参照（robot-oriented）：摇杆"向前"就是朝车头方向走。车头朝向一变，驾驶员就得在脑子里换算方向，很难开
  • 以场地为参照（field-oriented）：摇杆"向前"永远是朝场地对面走，不管车头朝哪。这是 swerve 的标准开法，驾驶员只管"往哪走"和"车头朝哪"两件事

以场地为参照需要实时知道机器人的航向角，所以依赖 IMU，见《传感器与视觉》。常见的手柄分配是：左摇杆控制平移方向和速度，右摇杆左右控制旋转。另外要注意，红方和蓝方站在场地两端，程序里要根据联盟颜色翻转"前方"的定义。

06软件实现

从零写一套 swerve 代码工作量不小。现在多数队伍从下面几种起点开始：

方案说明适合
CTRE Tuner X 生成器Phoenix Tuner X 里有 swerve 项目生成器：填好电机 ID、CANcoder ID、减速比等参数，自动生成整套代码使用 CTRE 电机（Kraken、Falcon）和 CANcoder 的队伍
REV MAXSwerve 模板REV 提供的 MAXSwerve 示例项目使用 REV MAXSwerve 轮组的队伍
YAGSL社区维护的通用 swerve 库，用配置文件描述硬件，支持多家厂商的电机和编码器混用多家硬件的队伍
基于 WPILib 自己写用 WPILib 的运动学、里程计类自己搭想深入理解原理、有经验的软件组

不管用哪种方案，核心都是下面几个 WPILib 类：

类作用
ChassisSpeeds机器人整体速度：前后、左右、旋转
SwerveModuleState单个轮组的目标：轮子角度 + 速度
SwerveDriveKinematics两者之间的换算，参数是四个轮组相对机器人中心的位置
SwerveDriveOdometry根据轮组状态和陀螺仪推算场上位置
SwerveDrivePoseEstimator在里程计基础上融合视觉测量

示意代码（Java，每 20 ms 执行一次）：

// 驾驶员输入 → 以场地为参照的机器人速度
ChassisSpeeds speeds = ChassisSpeeds.fromFieldRelativeSpeeds(
        vxMetersPerSec, vyMetersPerSec, omegaRadPerSec, gyroHeading());

// 换算成四个轮组的目标，并在超速时按比例缩小
SwerveModuleState[] states = kinematics.toSwerveModuleStates(speeds);
SwerveDriveKinematics.desaturateWheelSpeeds(states, MAX_SPEED);

// 每个轮组：转向电机跑角度闭环，驱动电机跑速度闭环
for (int i = 0; i < 4; i++) {
    modules[i].setDesiredState(states[i]);
}

每个轮组内部是两个闭环：转向电机的位置闭环和驱动电机的速度闭环，通常都在电机控制器内部运行，见《闭环控制与 PID》。具体类名和方法名以当年的 WPILib 版本为准。

07从零调通的步骤

  1. 核对硬件信息

    整理每个轮组的驱动电机 ID、转向电机 ID、CANcoder ID 和在底盘上的位置，填进配置。ID 规划见《CAN 数据总线》。

  2. 校准轮组零点

    把四个轮子都摆正，朝向车头前方，并保证驱动齿轮朝同一侧。记录此时每个 CANcoder 的读数，作为偏移量写进配置。

  3. 把机器人架空测试

    用支架把底盘垫起来，轮子离地。先只测转向：给一个角度，看四个轮子是否都转到同一方向。

  4. 检查驱动方向

    给一个"向前"的指令，确认四个轮子都朝前滚。哪个反了，就修改那个驱动电机的反转设置。

  5. 调转向闭环

    转向电机的位置 PID 要快而不振荡，轮子转到位后不能抖动。

  6. 落地慢速试车

    先限制最高速度，试前进、横移、原地旋转，再试边走边转。确认以场地为参照的方向正确。

  7. 测前馈、调速度闭环

    用 SysId 测驱动电机的前馈参数，再调速度 PID，见《闭环控制与 PID》的调参流程。

  8. 验证里程计

    让机器人走一段量好的距离，比较里程计读数和卷尺量出的实际距离。误差大，就检查轮子直径和减速比设置。

  9. 设置限制

    设电流限制防止打滑和掉电，根据驾驶员习惯设置最大速度、最大加速度。

先在仿真里跑

CTRE 生成器和 YAGSL 都支持仿真。在电脑上先确认手柄方向、场地参照、自动路线都正确，上车调试会顺利很多。

08选型与设计要点

  • 速度和加速度的取舍：场地小、需要频繁启停的赛题，加速度比最高速度更重要。可以用 ReCalc 等工具比较不同减速比
  • 底盘尺寸：大底盘更稳、放东西的空间大；小底盘更灵活、容易穿过狭窄区域。尺寸要先满足规则限制，并留出保险杠的位置
  • 重心要低：电池、底盘结构尽量放低。高重心的机器人急停、转弯、被撞时容易翻车
  • 底板和离地间隙：底板（belly pan）用来安装电气元件；离地间隙要能越过场上的障碍
  • 轮胎是消耗品：轮子表面的胎面会磨损，影响抓地力和里程计精度。比赛期间定期检查和更换
  • 预算：一套 swerve 要 8 个电机、4 个轮组和 4 个编码器，是全车最贵的部分之一，要提前规划

09坦克底盘要点

如果选择坦克式底盘：

  • 结构：左右各一组轮子，每侧一个减速箱，通常每侧 2 个电机。常见的 West Coast Drive 让中间轮子略低，转向时阻力更小
  • 驾驶方式：常用 arcade 方式，一个摇杆控制前后，另一个控制转向；也有 tank 方式，两个摇杆分别控制左右两侧
  • 软件：WPILib 的 DifferentialDrive 处理驾驶，DifferentialDriveKinematics 和 DifferentialDrivePoseEstimator 用于自动路线和定位
  • 仿真：可以先做《开发环境与仿真》里的练习 5，体验差速底盘的驾驶和自动路线

10常见问题

开机后有一个轮子朝向不对
这个轮组的 CANcoder 偏移量不对，或者 CANcoder 的 ID 和轮组对应错了。重新校准零点，核对 ID 表。
推摇杆向前，机器人却斜着走或者原地打转
检查顺序：轮组在程序里的位置是否和实际对应；某个驱动电机或转向电机的方向是否反了；陀螺仪的方向和安装设置是否正确。
机器人停下时轮子一直在抖
转向闭环的 kP 太大或 kD 不合适；也可能是没有速度指令时仍在不断调整角度。可以在速度接近零时保持轮子原来的角度不动。
开得越久，场上位置偏得越远
里程计误差在累积。检查轮子直径和减速比设置，轮胎是否磨损、是否打滑；再加上视觉定位来修正。
急加速时机器人"软"一下
8 个电机同时大电流，触发了掉电保护。设置驱动电机的电流限制，限制加速度，并检查电池状态。
